RuntimeGate — fail CI when runtime pins disagree, not the deploy

A small Node.js CLI that checks whether your Dockerfile, CI, and version files agree on Node.js, Python, or Go — and can optionally fail when a pin is past official end of support.

What it checks

  • runtimegate check — primary command
  • Node.js, Python, and Go version declarations in version files, manifests, Dockerfiles, Compose, and GitHub Actions setup-* steps
  • Errors when pins disagree on the compatibility series (Node major; Python and Go major.minor)
  • Errors when a pin cannot satisfy a declared engines or requires-python range
  • Optional --eol: fail when a pin is past official end of support (vendored dates, no network)
  • --json, --lang, --ignore, --root
  • Exit codes: 0 pass, 1 violations, 2 usage or missing root

What it is not

  • Not a full YAML or TOML parser
  • Does not expand Docker ARG interpolation
  • Does not call a live end-of-life API — dates are a snapshot in the package
  • Does not prove production is running the pin, only that declared pins agree
  • Lite (the GitHub Action) is Node.js only

Lite vs the full CLI

RuntimeGate Lite is a free GitHub Action that checks Node.js pins only. Use it as ESS2292/runtimegate-action@v1. The $19 CLI adds Python and Go, a JSON report, and a command you can run on a laptop or in any CI. Checkout is not live.

CI sketch

From the bundled workflow sketch. Prefer reading a version file in setup-node so CI cannot drift from the pin developers use.

.github/workflows/runtimegate-example.yml 
# Example only — copy into a consuming repository. The paid CLI is not published yet.
name: RuntimeGate

on:
  pull_request:
  push:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Install RuntimeGate
        run: npm install -g .

      - name: Check runtime version drift
        run: runtimegate check --eol

Honest limits

  • Workflow and Compose parsing is best-effort, not a complete YAML implementation.
  • requires-python is read from a simple assignment line in pyproject.toml.
  • A CI matrix is allowed to test several versions; entries still must satisfy a declared range.
  • End-of-support dates were snapshotted on 10 November 2026 from the official Node.js, Python, and Go schedules. Re-check the table when cutting a release.
  • On that snapshot, Node 20 ended 30 April 2026 and Python 3.10 ended 1 October 2026. Those are official dates, not estimates.

FAQ

Is this the same as EnvGate?

No. EnvGate checks environment files for missing keys, placeholders, and a narrow set of secret shapes. RuntimeGate checks whether runtime version pins agree. They share an audience (CI and DevOps) and the same “fail the job, not the deploy” idea.

Why $19 if the source is MIT?

MIT allows selling copies. The price is for a packaged, tested release with docs and a CI sketch, not exclusive ownership of the code. Buyers (and others) may redistribute under MIT terms.

Does --eol need network access?

No. Dates are vendored in the package, with sources cited in the docs. They can go stale; the snapshot date is printed in src/eol.js.

Where is the free GitHub Action?

RuntimeGate Lite is published at ESS2292/runtimegate-action. Use ESS2292/runtimegate-action@v1. It checks Node.js pins only. Questions can be opened as GitHub Issues.
