What it checks

  • runtimegate check — primary command
  • Node.js, Python, Go, and Rust version declarations in version files (including .tool-versions and mise.toml), manifests (including Volta, Pipfile, and go.work), Dockerfiles (including Dockerfile-CUDA and *.dockerfile), Compose, devcontainer.json, and GitHub Actions setup-* steps
  • Errors when pins disagree on the compatibility series (Node major; Python, Go, and Rust major.minor)
  • Errors when a pin cannot satisfy a declared engines or requires-python range
  • Optional --eol: fail when a pin is past official end of support (vendored dates, no network)
  • --json, --lang, --ignore, --root, --engines-scope
  • Exit codes: 0 pass, 1 violations, 2 usage or missing root

What it is not

  • Not a full YAML or TOML parser
  • Does not expand Docker ARG interpolation
  • Does not call a live end-of-life API — dates are a snapshot in the package
  • Does not prove production is running the pin, only that declared pins agree
  • Lite (the GitHub Action) is Node.js only

Lite vs the full CLI

RuntimeGate Lite is a free GitHub Action that checks Node.js pins only. Use it as ESS2292/runtimegate-action@v1. CI sketch

From the bundled workflow sketch. Prefer reading a version file in setup-node so CI cannot drift from the pin developers use.

.github/workflows/runtimegate-example.yml 
# Example only — copy into a consuming repository. The paid CLI is not published yet.
name: RuntimeGate

on:
  pull_request:
  push:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Install RuntimeGate
        run: npm install -g .

      - name: Check runtime version drift
        run: runtimegate check --eol

Honest limits

  • Workflow, Compose, and mise.toml parsing is best-effort, not a complete YAML or TOML implementation. Inline comments, GitHub-style 20.x matrix values, and major-only Actions pins such as node-version: 22 are supported.
  • requires-python is read from a simple assignment line in pyproject.toml. Dockerfile names such as Dockerfile-CUDA and *.dockerfile are recognized by a filename heuristic, not a formal Docker specification.
  • A go.work go line is a workspace minimum, not a pin: a lower go.mod language version is allowed. Rust pins are compared for drift; --eol does not classify Rust because rustup has no versioned end-of-support table in the vendored snapshot.
  • A CI matrix is allowed to test several versions; entries still must satisfy a declared range in the same workspace. By default, engines and requires-python are scoped to the package that declared them (GitHub workflows count as the repo root). Use --engines-scope all (or the Action input engines-scope: all) to compare every range to every pin.
  • Directories named build are skipped as compile output, except under docker/ or dockerfiles/, so paths such as docker/build/x86_64/Dockerfile are still scanned.
  • End-of-support dates were snapshotted on 10 November 2026 from the official Node.js, Python, and Go schedules. Re-check the table when cutting a release.
  • On that snapshot, Node 20 ended 30 April 2026 and Python 3.10 ended 1 October 2026. Those are official dates, not estimates.

FAQ

Is this the same as EnvGate or LockGate?

No. EnvGate checks environment files for missing keys, placeholders, and a narrow set of secret shapes. RuntimeGate checks whether runtime version pins agree. LockGate checks whether the dependency install is frozen and repeatable. The free LockGate Lite Action fails the job when mixed lockfiles are committed or CI runs an unfrozen install. They share an audience (CI and DevOps) and the same “fail the job, not the deploy” idea.

Why $19 if the source is MIT?

MIT allows selling copies. The price is for a packaged, tested release with docs and a CI sketch, not exclusive ownership of the code. Buyers (and others) may redistribute under MIT terms.

Does --eol need network access?

No. Dates are vendored in the package, with sources cited in the docs. They can go stale; the snapshot date is printed in src/eol.js.
